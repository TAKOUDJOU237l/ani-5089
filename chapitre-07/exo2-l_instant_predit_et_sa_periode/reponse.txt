Ce qui est stable : Dans les vingt lignes, « ecart » vaut 13,889 ms à chaque ligne, sans exception. Mais ce n'est pas une mesure : mon code calcule predit = maintenant + periode, donc ecart = periode par construction, et il ne peut pas varier. Ce qui n'est pas stable vient de la machine : « maintenant » avance de 64,8 à 77,0 ms d'une image à l'autre (moyenne d'environ 70,9 ms sur ces vingt lignes), et non de 13,889 ms. Sur les quatre lancements de 600 images, l'intervalle moyen entre deux débuts d'image reste entre 73,9 et 79,6 ms, soit environ 13 images par seconde, alors que la période demandée varie de 8,3 à 16,7 ms. La constante est dans mon code, la variabilité est dans la machine : c'est pour cela qu'il faut comparer la prédiction à ce qui arrive, et non à elle-même.

Un divisé par la cadence : 1000 / 60 = 16,667 ms, 1000 / 72 = 13,889 ms, 1000 / 90 = 11,111 ms, 1000 / 120 = 8,333 ms. Les quatre lignes de instants.txt donnent exactement ces quatre périodes.

La période de mon écran : Je ne peux pas la déduire de mes mesures, et je le dis. Le début réel d'une image vaut predit + (reel - predit), donc l'intervalle réel entre deux débuts d'image = période annoncée + (reel - predit). Cela donne : 60 Hz : 16,667 + 61,228 = 77,895 ms ; 72 Hz : 13,889 + 65,748 = 79,637 ms ; 90 Hz : 11,111 + 62,761 = 73,872 ms ; 120 Hz : 8,333 + 71,174 = 79,507 ms. Si l'écran fixait le rythme, ces quatre totaux seraient égaux à sa période. Ils ne le sont pas : ils varient de 73,9 à 79,6 ms alors que la période demandée a varié de 8,3 à 16,7 ms, et ils sont tous bien au-dessus de la période d'un écran courant (l'inverse de 77 ms est 13 Hz). C'est donc mon programme qui fixe le rythme, pas l'écran : chaque image prend environ 75 ms à produire, et l'écran attend. La période de mon écran n'apparaît pas dans ces mesures. Les paramètres d'affichage de Windows indiquent 60 Hz, soit une période de 16,667 ms (valeur relevée à l'exercice 1) : mes quatre totaux ne la retrouvent pas, puisque la machine fixe le rythme, donc je ne peux ni confirmer ni infirmer cette valeur avec mes mesures, je m'en tiens à celle de Windows. Conditions : Release, MASALLE_POST=0 (effets d'image coupés), un lancement par cadence ; en Release sans MASALLE_POST=0, les trois premières mesures donnaient 88,9 (72 Hz), 80,9 (90 Hz) et 85,2 ms (120 Hz), donc aucun changement notable.
